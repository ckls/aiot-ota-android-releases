# 0.3.24：手动报告目录筛选与 Model→SPEC 标识选择

- 新增平台报告目录的手动筛选：按报告 ID、产品、固件版本、用例标题，以及可选的成对开始／结束日期查询；每次手动查询一页，只读展示目录元数据。不会自动轮询、打开报告链接或执行上传、导出、设备写入操作。
- 离线 SPEC 对比增加可选的 Model→完整 URN 查询与选择：选中的标识只用于约束手动粘贴的 A/B JSON 类型，不自动获取公共 SPEC JSON；未登录时仍可使用原有手动 JSON 对比。
- 保留既有手动 PDID 产品查询、脱敏报告说明本地检索、平台公告、设备调试、OTA 和 BL616 SerialLab 功能。本次不新增固件或设备控制，也不宣称与 Windows 工具完全等价。

验证范围：本次完整主机验证的 20 个规范阶段、13 个外层阶段及 7 项显式守卫已通过；Python 源码测试 320 项、发布测试 88 项，另有 1758 个验收器负例检查。报告目录与 Model/SPEC 专项及实际编译证据均通过，生产输入为 115 个 Java 源文件、122 项编译输入。这些是不同层级的执行计数，不能相加当作去重后的覆盖总数；主机合成、编译与构建证据不代表手机或硬件验收。

保留验证过程中的失败记录：首次本地定点验证因日期检查规则误将 LocalDate.parse 识别为旧接口而失败，随后仅修正测试规则；第二次本地恢复在既定 Python 阶段时限耗尽后停止，不能记为通过。之后未扩大本地时限或重复本地全套，改由相同最终源码的新完整主机验证建立当前验收。首次数据验收另因冻结状态元数据不匹配而停止，保留失败，仅修正该元数据后重放数据验收，未重跑构建。0.3.23 曾出现的本地工作线程等待超时根因仍未确定，不据此宣称已修复。
