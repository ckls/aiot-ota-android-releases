# 0.3.25：手动固件包资料查询与报告用例标题选择

- 新增按完整 Model 手动查询固件包历史资料：只读展示平台返回的任务标识、文件名、声明的 MD5 与时间文本，支持本地分页。平台声明的 MD5 不代表已经校验固件内容；本功能不下载固件、不生成差分包、不发起 OTA，也不绑定或写入设备。
- 报告目录增加可选的版本 4 用例标题选择器；该目录范围不代表所有测试类别。只允许选择可以安全、完整显示的标题，填入现有筛选框后仍需再次手动查询报告；原有自由输入保留，不会自动查询报告、打开链接或保留隐藏的敏感标题。
- 修正主界面两处说明：报告、进度和历史入口只读；已保存定义仍仅在明确确认后提交受限 READ_PROP 测试并创建云端任务。本次没有改变该既有行为，也不把它描述为服务端或设备绝无其他作用。
- 保留既有报告筛选、Model→URN 与手动 JSON 对比、PDID 产品查询、脱敏说明本地检索、公告、设备调试、OTA 和 BL616 SerialLab 功能；仍不自动获取公共 SPEC JSON，不宣称已实现 Windows 工具完整功能等价。

验证范围：最终源码的新完整主机验证通过 20 个规范阶段、13 个外层阶段和 7 项显式守卫；Python 源码测试 343 项、发布测试 88 项，另有 2217 个数据验收负例检查。固件资料与用例选择专项、实际编译日志和生成的主界面测试输入均通过；生产输入为 122 个 Java 源文件、129 项编译输入。这些是不同层级的执行计数，不能相加当作去重后的覆盖总数；主机合成测试和构建通过不等同于手机或硬件验收。

失败记录保留：早期本地固件界面阶段与后续主界面源码解析阶段分别触及时限，均仍记为失败；单独的固件界面诊断未复现等待，根因并未据此确认。第一次完整主机验证中，343 项 Python 测试有一项错误依赖字典引号写法；只修正该测试的语法树判定，并验证同一项测试的正反例，未改变产品代码。之后另一次新完整主机验证建立本次验收，没有把旧失败记录拼接或改写为通过。原有 0.3.23 本地工作线程超时及 0.3.24 的历史失败记录也未被抹去或宣称已经修复。

APK 已通过原证书 v2/v3 签名核验，非签名应用内容与已验未签名构建逐成员一致。公开下载附件仅为 APK、更新清单和校验和；签名与字节一致性不代表安装或原地升级已经验证。
